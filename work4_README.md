# Лабораторная работа 4 — голосовое управление умным домом

Подготовлено по разделу «Четвертый проект», страницы 92–105 методички
Raspberry_ru.pdf. Оборудование: **Raspberry Pi 5, BME280 или BMP280, WS2812B и настоящий
Android-телефон**. Arduino и MQTT в этой работе не нужны.

## Что делает система

После нажатия Talk телефон распознаёт английскую фразу, отправляет команды
на Raspberry Pi по HTTP и озвучивает ответы на английском. BME280 измеряет
температуру, влажность и давление; BMP280 — температуру и давление.
Тип датчика определяется автоматически. Светодиодная лента включается белым,
красным, зелёным, синим, жёлтым, фиолетовым или случайным цветом и выключается.

```text
Голос → Android (распознавание речи) → HTTP → Raspberry Pi
                                              ├── I2C → BME280 / BMP280
                                              └── SPI или PIO → WS2812B
Телефон ← ответ сервера ←─────────────────────────┘
    └── TextToSpeech: озвучивание ответа
```

## Порядок запуска

1. Собрать схему и запустить сервер по
   [инструкции для Raspberry Pi](work4_3_raspberry_server/README.md).
   Способ управления лентой нужно выбрать до подключения: **SPI — GPIO10,
   физический контакт 19; PIO — GPIO18, физический контакт 12**.
2. Узнать адрес Pi командой `hostname -I`. Подключить телефон и Pi к одной
   сети Wi-Fi без изоляции клиентов.
3. На телефоне открыть в браузере `http://IP_МАЛИНЫ:8000/temperature`.
   Если показание отображается, сервер доступен телефону.
4. В Android Studio открыть именно папку `work4_2_voice_android` и дождаться
   Gradle Sync. Затем подключить телефон и нажать Run:
   [подробная инструкция для Android](work4_2_voice_android/README.md).
5. В приложении вписать `http://IP_МАЛИНЫ:8000/`, нажать Talk и произнести
   одну из команд ниже.

## Запуск после перезагрузки Raspberry Pi

На настроенной Raspberry Pi лента подключена к **GPIO18, физическому
контакту 12**, поэтому используется режим **PIO**. BME280 найден по адресу
**0x76**, в настройках ленты указано **8 светодиодов**.

После перезагрузки откройте терминал Raspberry Pi и выполните:

```bash
cd ~/Downloads/hse-arduino-main/work4_3_raspberry_server
.venv/bin/python server.py --led-backend pio --address 0x76 --pixels 8
```

Это фактическая папка проекта на настроенной Raspberry Pi. Если проект
перенесён в другую папку, измените только путь в команде `cd`.

Оставьте терминал открытым во время работы. Остановка сервера — **Ctrl+C**.
Автозапуск при включении Raspberry Pi не настроен: после перезагрузки
сервер запускается вручную этой командой. Повторно устанавливать библиотеки
после обычной перезагрузки не требуется.

При настройке адрес Raspberry Pi был **10.167.32.100**. В Android-приложении
используется:

```text
http://10.167.32.100:8000/
```

После перезагрузки проверьте IP командой `hostname -I`. Если он изменился,
обновите адрес в приложении, сохранив порт `8000`. Телефон и Raspberry Pi
должны быть в одной локальной сети.

Для проверки с телефона откройте в браузере:

```text
http://10.167.32.100:8000/temperature
```

## Нужно ли перезапускать Android-приложение

Исправление ошибки «каждый запрос проходит со второй попытки» сделано
**только в сервере на Raspberry Pi**. Для этого сетевого исправления
пересобирать или переустанавливать Android-приложение не требуется.

При обновлении проекта для BMP280 приложение нужно один раз обновить через
Run в Android Studio: изменилось озвучивание ответа о недоступной влажности.

После перехода со старой версии сервера на исправленную один раз закройте
приложение из списка недавних приложений и откройте снова. Это удалит старое
закрытое соединение из пула клиента.

После обычной перезагрузки Raspberry Pi достаточно запустить сервер.
Перезапуск Android-приложения каждый раз не нужен; при изменении IP нужно
обновить адрес в его поле настроек.

Причиной запросов «через раз» было повторное использование закрытого
HTTP-соединения в OkHttp 3.6.0. Сервер теперь явно передаёт `Connection: close`.
На настоящей Raspberry Pi проверено: **8 последовательных запросов тем же
OkHttp прошли без ошибок**.

## Команды для защиты

| Что сказать | Результат |
|---|---|
| Tell me the temperature | Температура в °C |
| Tell me the pressure | Давление в мм рт. ст. |
| Tell me the humidity | Влажность BME280 в %; для BMP280 — сообщение, что он её не измеряет |
| Tell me the sensor data | Температура, давление и влажность либо сообщение о её отсутствии |
| What is the weather forecast? | Учебный прогноз по давлению |
| Turn on the lights | Белый цвет |
| Turn on the lights, color red | Красный |
| Turn on the lights, color green | Зелёный |
| Turn on the lights, color blue | Синий |
| Turn on the lights, color yellow | Жёлтый |
| Turn on the lights, color purple | Фиолетовый |
| Turn on the lights, color random | Случайный цвет всей ленты |
| Turn off the lights | Выключение |

Длинная проверка из методички:

> So, tell me the sensor data and also separately the values of temperature,
> pressure and humidity along with the weather forecast, and switch the
> lights on, color random.

Приложение запросит показатели, прогноз и случайный цвет. С BMP280 оно
сообщит, что влажность недоступна, и продолжит остальные команды. Повторные
упоминания показателей не создают дубликатов. Запросы идут последовательно
в фоновом потоке, поэтому интерфейс не зависает. После ответа сервера телефон
прочитает результаты в том же порядке.

## Что объяснить преподавателю

- RecognizerIntent запускает системное окно распознавания. Возвращённая
  строка разбирается на команды с учётом границ слов.
- OkHttp передаёт GET-запросы на сервер; TextToSpeech читает результат.
- HTTP-сервер читает BME280 по I2C и отправляет данные ленте через выбранный
  аппаратный интерфейс. Все светодиоды получают один RGB-цвет.
- BME280 и BMP280 возвращают давление в hPa. Для мм рт. ст. сервер делит его на
  1.33322387415. Пороги прогноза из методички — 1022.69 и 1009.14 **hPa**.
- Прогноз — учебное правило по текущему давлению: устойчиво / облачно /
  дождливо. Это не онлайн-прогноз и не анализ изменения давления во времени.
- В этой работе смартфон общается прямо с Raspberry Pi; облачные каналы
  ThingSpeak из работы 3 здесь не используются.

## Сценарий показа

1. Показать BME280, ленту и запущенный `server.py`.
2. Запустить приложение через Run на телефоне, указать адрес Pi.
3. Запросить `sensor data` и показать значения вместе с озвучиванием.
4. Запросить `weather`.
5. Включить красный, затем случайный цвет; выключить свет.
6. Произнести длинную команду и показать журнал HTTP-запросов на Pi.

Для защиты нужен запуск с настоящим оборудованием. `--demo` предусмотрен
для проверки связи до сборки схемы и отдаёт фиксированные тестовые значения.

## Если подключён BMP280

Получите обновлённые `server.py`, `hardware.py` и `requirements.txt` из проекта.
В папке сервера на Raspberry Pi выполните:

```bash
.venv/bin/python -m pip install -r requirements.txt
```

Затем запустите сервер обычной командой из раздела выше. Дополнительный
параметр выбора датчика не нужен: `0x58` распознаётся как BMP280, `0x60` —
как BME280. В `--address` указывайте I2C-адрес 0x76 или 0x77, а не 0x58.
На телефоне обновите приложение через Run в Android Studio.

На защите поясните, что BMP280 физически не измеряет влажность. Покажите
температуру, давление, прогноз, голосовое управление лентой и сообщение о
недоступной влажности.

В корне проекта:

```powershell

& .\work4_2_voice_android\check-parser.ps1
```

Компиляция и Android Lint выполняются без создания отдельного APK:

```powershell
Set-Location D:\Projects\hse-arduino\work4_2_voice_android
$env:JAVA_HOME = 'D:\Projects\hse-arduino\tools\jdk21\jdk-21.0.12.1+1'
$env:GRADLE_USER_HOME = 'D:\Projects\hse-arduino\android-data\gradle'
.\gradlew.bat :app:compileDebugJavaWithJavac :app:lintDebug
```

Автоматические проверки не заменяют проверку микрофона, английского TTS,
датчика и реальной ленты на ваших устройствах.

Если на Raspberry Pi установка прерывается на сборке `lgpio`, используйте
системный пакет `python3-lgpio` и окружение с `--system-site-packages`.
Команды восстановления и проверки `board` приведены в
[инструкции сервера](work4_3_raspberry_server/README.md).
